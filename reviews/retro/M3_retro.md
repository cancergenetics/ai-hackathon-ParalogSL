## 1. What should we stop doing?

1. **Starting production runs on uncommitted code, again.** M1 lesson 7 existed and was still violated. Evidence: D13 (human/arabidopsis/worm Tier A re-runs started from uncommitted code; `git_head_at_run` predates the change); D18 (the thinning run imported an uncommitted `eval/dataset.py` edit from the final_test agent, saved only because N->N reproduced 0.1432 exactly); Tier C review (tables stamped `src_dirty=True`, differing HEADs for yeast vs human; fixed only by the clean re-run 00991c6). Fix: make the run scripts refuse a dirty tree (or at least refuse to stamp a "clean" hash), instead of relying on the lesson text.
2. **Several agents editing shared files in one working tree.** Evidence: 415356b (shared-index race, M1) recurred as D18 (above), the final_test review R7 (registry `columns_hash`, model.py and train.py "in flight" while the script was being reviewed) and the 699d037 message (G1 test failing only because of untracked reviewer scripts). Fix: one owner per file per phase, and reviewers and experiment runs work from a worktree at a named commit.
3. **Hashing the whole registry into every feature table.** Any registry edit invalidated all 12 tables even when the columns were unchanged; it forced 239c3fd (a restamp script plus `columns_hash`) in the middle of the freeze, and `table_failures` in final_test.py still compared the global hash (final_test review R7). Use per-table column-definition hashes from the start (now done).
4. **Writing a brief or D-note from memory of the pre-registration instead of the spec.** The final_test review's Q1 found the brief's premise wrong: labelled pairs the caller misses are NOT in the primary population (DESIGN §6.2, statistics R2 item 5), they belong only to end-to-end. D17 itself had said otherwise and D19 had to correct it. The review caught this before the access, but nobody had checked it before the brief. Quote the section number being implemented in every brief.
5. **Building and reviewing a full tier before a cheap increment check.** Tier C (ESM-2 embeddings, ~100 min human in Low Power Mode, per D17) took df2afcd, dc1307c, 8bfad79, 22a390b, 00991c6 and an independent review, and was then not adopted (D17b: increment ~0.014 human, ~0.000 yeast; A+C vs A CIs included 0 in D14). It cost compute, reviewer time and a `plm` extra (D16). Gate such tiers on a small-subset, dev-only increment test first, and give non-adopted tiers a lighter review.
6. **Re-running dev batches because exclusions were found after the fact.** `tb_asym_*` features were in the d2d1c7b run, then the Tier B review (i) excluded them (6bb9438), requiring 6e3c00a plus a full re-run (e6849e8). Missingness checks (per species, per feature) belong before the first dev batch that includes a new tier.
7. **Restating the adoption rule after seeing dev results.** D12(b), the stratum guard, was added because Tier A "gains" turned out to be learned ascertainment; 95ac397 then says the rule was "restated by the PI". The rule was right and only dev data had been seen, so there was no harm, but the pattern (rule edited mid-stream, 144 configurations by D12, 663 rows in experiments.tsv) is where an inflated T would come from. Freeze the adoption rule and the candidate list before the first batch of a new family.
8. **Bookkeeping in the tree.** RESEARCH_TREE.md is now 21 KB (it was ~10 KB at M1); D9, D11, D13 and D19 still carry hash prefixes and counts that live in `config/protected.sha256` and `results/*.json` (M1 retro item 6 not acted on). The Tree section is stale: item 5.2 appears twice, items 6.3 onward do not exist, 7 (CLI, shipped in 699d037) and 8 are unchecked. Trim decision notes to decision, why, pointer; update the Tree at each milestone.
9. **Timing under non-clean machine state.** D13's 7,057 s human run was at load average 95-154 (explicitly "not a clean benchmark"); D20 still lists an idle-machine benchmark as open. M1 lesson 9 covered power state only; add load.

## 2. What worked well (keep)

1. **Adversarial, measurement-based reviews at decision points.** The Tier B gain review (457ed8c, D17) reproduced T_pf exactly, ran row-shuffles (0.143 -> 0.040), regrouping and source-library controls, and returned PARTLY ARTEFACT (within-cell gain +0.010, covariate-adjusted +0.015). The final test then showed exactly that pattern (within identical ascertainment cells -0.020 [-0.098, 0.060]; D20), so the report can state it honestly instead of being surprised by it. Review of Tier B (e035f77) caught `tb_asym_*` (D14) and the yeast WGD limitation; harness review (1c8b370) produced the D12 guard.
2. **Reviewing the irreversible step before it ran.** final_test.py review (8ecda54) found R1 (nothing pinned the model to GBDT_AB_17), R2 (eight pre-registered secondaries missing, unrecoverable after access) and R3 (a secondary failure would discard the primary); fixed in 563b15d, re-review READY (29e8fc8), then D19 froze and the one access went clean with no secondary errors (D20).
3. **Pre-declaration commits before the run.** 2ab485d, 6e3c00a, 048c11a, b2cf739 are declare-only commits referenced by the results; adoption by rule (D15, D17a) and D18's "NOT adopted by the declared rule" show the rules constrained decisions in both directions. D17(c) fixed the test secondaries before the access, which is why the ascertainment and Arabidopsis non-gain results are reported, not hidden.
4. **Controls and invariants as standing outputs:** shuffled-label AP at prevalence, species-ID and source-library AUROCs, Tier B row shuffle, thinning test (D18), per-fold paired ΔAP (D12a), B2 and B4 baselines, per-species CIs. The yeast-only-trained model on human test (0.259 vs 0.106) is what lets D20 claim transferable signal.
5. **Negative results recorded as decisions:** Tier C not adopted (D17b), masking not adopted (D18), identity-anchored candidates fail the guard (D15), Arabidopsis non-gain kept exploratory, no retuning (D20).
6. **Independent re-implementation and known-answer checks** continued to find nothing wrong in feature values (Tier B: all 200-pair recomputations agreed; Tier C: max diff ~1e-15) while finding test gaps (scrambled ID mapping in run_tierB/run_tierC untested), which then got regression tests (5e86b6a, 8bfad79).
7. **Label-blind feature agents and the sealed-data guards** (D7, D19 protected list and guard tests) held through M2-M4: no incident after D10.
8. **Fixing the frozen model by spec, not by file:** `frozen_spec_failures` derives the expected model from config and registry (563b15d), and the model is tagged and hashed (D19).

## 3. Proposed LESSONS.md (10 one-line rules)

1. Write one normative spec (no "unless this file says otherwise"), dry-run every threshold, cap or split rule label-blind on the real structure, and cap the unit you actually fear; evidence: round 3 found 14 contradictions (D4); a 1,611-pair family took 18% of human pairs into test (D9).
2. Quote the pre-registered section in every brief and D-note; a recalled definition is not a spec; evidence: the final_test review found the brief's primary-population premise wrong (DESIGN §6.2) and D19 had to correct D17.
3. Forbid scoring labelled pairs in every builder/reviewer brief, give them no split membership, and list every sanctioned sealed reader in the guard at creation; evidence: D10 (identity AP on unsplit labels), D5 (G1 failed on the known-answer tests).
4. Commit code, then run production steps from a clean tree and record that hash (scripts should refuse a dirty tree); evidence: D13 and D18 (runs from uncommitted code), the Tier C meta `src_dirty=True` (re-run 00991c6), the yeast labels review finding 3.
5. One owner per file and one agent per working tree at a time; commit with `git commit <paths>`; evidence: 415356b shared-index race, D18's imported uncommitted edit, final_test review R7.
6. Stamp each artifact with a hash of its own column or parameter definitions, not of the whole registry; evidence: 239c3fd had to restamp all 12 tables, and final_test review R7 found the global hash still checked.
7. Declare rules and candidates in a commit before the run: adoption rule, secondaries, ablation sets, and per-feature missingness checks; evidence: 2ab485d, 6e3c00a, 048c11a, D17(c); the unchecked `tb_asym_*` forced a full re-run (6bb9438).
8. Run an adversarial, measure-on-real-data review before adopting any gain and before any irreversible step (one-shot test access, freeze); evidence: D17 (PARTLY ARTEFACT, later confirmed by the -0.020 within-cell test result), final_test review R1-R3 (fixed before the access), rounds 1-2 measurements.
9. Report every headline gain next to a confound-controlled version (within ascertainment cells, strata, source library, yeast-only transfer, unseen species); evidence: D12(b), D17, D20 (T = 0.297 headline vs -0.020 within cells).
10. Smoke-test new pipelines on ~5% before a full run, gate expensive tiers on a dev increment check, and record power state and load average with every timing; evidence: D11 (2.3 h run, 67% flagged), Tier C not adopted (D17b), D13 (load 95-154).
