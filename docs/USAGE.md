# slparalog

Predict synthetic-lethal (SL) paralog pairs from a eukaryote proteome FASTA alone. Every feature is computed
from the sequences (self-search, a reference panel of 80 proteomes, ESM-2 embeddings); no expression, interaction,
essentiality or annotation data is used.

Status: released. The release model is `results/release/model` (AB-gbdt-332d4d20: GBDT on Tier A + Tier B features,
refit on all human and yeast labels); install it with `slparalog setup --model results/release/model`. The model evaluated
on the held-out test set is `results/frozen/model` (AB-gbdt-7ff069ac, tag `final-model-v1`). Results: REPORT.md.

## Install

Requires Python >= 3.12 and the pinned MMseqs2 binary at `bin/mmseqs` (version and checksum in
`config/tools.yaml`; `setup` does not fetch it).

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e .                      # numpy, pandas, scikit-learn, pyyaml, numba, pyarrow, psutil
pip install torch transformers huggingface_hub   # only for Tier C (ESM-2 embeddings) and `setup --plm`
pip install -e ".[dev]"               # pytest, for the test suite
```

The editable install is required: the configuration (`config/`) is read from the checkout.

## Set up

```bash
slparalog setup                        # panel + ESM-2 weights  (= --panel --plm)
slparalog setup --panel                # 80 panel proteomes (sha256-verified), assembled panel, per-species MMseqs2 DBs
slparalog setup --plm                  # ESM-2 150M at the pinned revision (sha256-verified)
slparalog setup --model path/to/model  # validate a model artifact and install it as the default model
```

Everything goes under the data directory: `--data-dir`, else `$SLPARALOG_DATA`, else `~/.slparalog`
(`panel/` about 2.5 GB: 0.7 GB FASTA + 1.4 GB databases, plus the hit cache that grows per query proteome; `plm/` about 0.6 GB). Sources and checksums are
`config/panel_species.tsv`, `config/data_manifest.yaml` and `config/panel_sources.json` (panel) and
`config/plm_weights.json` (weights); the last two are generated by `scripts/data/make_setup_checksums.py`.
Downloads are written to `*.part` and renamed only after the checksum matches; re-running skips verified files,
so `setup` is idempotent. Only Tier A needs nothing from `setup`; a model that uses Tier B needs `--panel`,
Tier C needs `--plm`.

## Predict

```bash
slparalog predict proteome.faa -o pairs.tsv --model path/to/model -t 4
slparalog predict proteome.faa -o pairs.tsv                 # uses the model installed by `setup --model`
slparalog predict proteome.faa -o features.parquet --features-only [--tier-b] [--tier-c]   # no model
```

Without `--model` and without an installed model, `predict` keeps its legacy output (features with NaN `sl_score`/`sl_rank`
placeholders and a note on stderr).

`predict` computes exactly the tiers the model needs (`required_tiers` in `model.json`): Tier A (self-search and
paralog calling) always, Tier B (panel search) and Tier C (ESM-2 embeddings, in a child process; torch is never
imported into the scoring process) only if the model uses a feature of that tier. Use `--plm-cache DIR` to reuse
embeddings across runs.

### Output

Tab-separated, one row per called pair, sorted by `sl_rank`. The file starts with a `#` comment block: tool version,
model id, input path and sha256, number of proteins and pairs, tiers computed, run time, and the QC warnings. Read
it with `pandas.read_csv(path, sep="\t", comment="#")`. `pairs.tsv.meta.json` holds the full run metadata.

| column | meaning |
|---|---|
| `gene_a`, `gene_b` | the pair (FASTA ids, `gene_a < gene_b`) |
| `sl_score` | model score in [0, 1]. A ranking score; **not** a calibrated probability of SL (training weights equalise species and prevalence) |
| `sl_rank` | 1 = highest score; ties share the best rank |
| `ident_global` | global Needleman-Wunsch identity of the pair (BLOSUM62, 11/1, end gaps penalised) |
| `fragment_suspect` | 1 if either protein is shorter than half the median length of its called partners |
| `near_identical` | 1 if local identity >= 0.99 (possible allelic copy or isoform) |
| `n_dir_called` | search directions in which the pair was called (1 or 2) |
| `tb_fragment_suspect`, `tb_n_outgroups` | Tier B only: fragment flag from panel best hits; outgroup triplets available (0-3) |

QC warnings in the header (and on stderr) are proteome-level: no pairs called, a panel core set that is too small
(divergence calibration unreliable), the nearest panel species being far away (young duplications unresolvable), a
different MMseqs2 binary than the pinned one, empty or non-standard input records.

## Train a model

```bash
slparalog predict human.faa -o human_feats.parquet --features-only --tier-b -t 8
slparalog predict yeast.faa -o yeast_feats.parquet --features-only --tier-b -t 8
slparalog train --features human=human_feats.parquet --features yeast=yeast_feats.parquet \
                --labels human=data/labels/dev/human_dev.tsv --labels yeast=data/labels/dev/yeast_dev.tsv \
                --feature-set A+B --model-type gbdt -o models/ab_gbdt
```

`train` reuses the harness code (`slparalog.eval`): species-balanced weights, the fixed settings and the recorded
hyper-parameter configuration of `config/models.yaml`; `--param KEY=VALUE` accepts only values of the declared grid.
Labels are read through `io.labels.load_labels`, which refuses the held-out label directory. To refit the released
model on all labelled data, pass all development label tables. Feature sets are registry tiers or Tier A groups
joined by `+` (`A`, `A+B`, `A+B+C`).

A model artifact is a directory with `model.joblib` and `model.json` (feature list, feature set, registry hash,
required tiers, scikit-learn version, checksums of the training labels and feature tables, git commit, seeds,
hyper-parameters). Loading fails with a clear error if the registry hash or `config/caller.yaml` changed since
training, a listed feature is not registered, the estimator's columns differ from the list, the `joblib` file does not
match its checksum, or the scikit-learn minor version differs (`--allow-sklearn-mismatch` overrides the last one).
`model.joblib` is a pickle: only load models you trust.
